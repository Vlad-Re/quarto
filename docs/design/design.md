# Дизайн (v1.0)

Рішення зібрані з раундів дизайну. Обґрунтування — у `docs/decisions/` (ADR 0011–0019).

## 1. Парадигма

- Стиль Rust: незмінні структури (`@dataclass(frozen=True)`), вільні функції, `Enum` + `match` з перевіркою вичерпності, без ієрархій наслідування.
- Виняток: вікно наслідує `tk.Frame`.
- «Trait» за потреби — `Protocol`; у v1.0 не використовується.

## 2. Доменна модель

Фігура
- `Piece = NewType("Piece", int)` — число 0–15, біт = атрибут.
- Маски атрибутів (біт 0 — крайній правий):
  - `SHAPE = 0b0001` — у view.md «біт 1»: 0 коло, 1 квадрат
  - `COLOR = 0b0010` — «біт 2»: 0 світла, 1 темна
  - `SIZE  = 0b0100` — «біт 3»: 0 мала, 1 велика
  - `HOLE  = 0b1000` — «біт 4»: 0 суцільна, 1 з отвором
- Виведення в бітовій нотації: `f"{piece:04b}"`.
- Лінія виграшна, якщо AND чотирьох фігур ≠ 0 (спільна одиниця) або AND їхніх інверсій (`~p & 0b1111`) ≠ 0 (спільний нуль).

Клітинка і дошка
- `Cell = NewType("Cell", int)` — індекс 0–15, `cell = row * 4 + col`.
- Дошка — `tuple[Piece | None, ...]` довжиною 16.
- `LINES` — 10 заздалегідь заданих кортежів з 4 клітинок: 4 рядки, 4 стовпці, 2 діагоналі.

Сторона і дія
- `Side` (Enum): `FIRST`, `SECOND`. За правилами FIRST — той, хто віддає першу фігуру (у v1.0 бот), SECOND — той, хто ставить першим (у v1.0 гравець). Модель не знає, хто з них бот; це вирішує презентер.
- `Action` (Enum): `PLACE`, `GIVE`.

Стан гри — `GameState` (frozen)
- `board` — дошка;
- `available: frozenset[Piece]` — фігури, які ще можна віддати (без поточної);
- `current: Piece | None` — фігура, яку треба поставити;
- `side: Side` — чия черга;
- `action: Action` — який крок зараз.
- Історії ходів немає. Undo (у наступних версіях) — презентер пам'ятає попередній стан.

Хід бота — `Move` (frozen)
- `cell: Cell` — куди поставити поточну фігуру;
- `piece: Piece | None` — яку віддати; `None`, якщо після постановки гра закінчилась.

Результат гри
- `Win` (frozen): `side: Side`, `line: tuple[Cell, Cell, Cell, Cell]`.
- `Draw` (frozen), без полів.
- `Outcome = Win | Draw | None` (None — гра триває).
- Результат не зберігається в стані, а обчислюється з дошки.
- Якщо виграшних ліній кілька — повертається перша в порядку `LINES` (рядки, стовпці, діагоналі).

Виняток
- `IllegalMove(Exception)` — недозволений хід. Сигнал бага у вікні чи презентері.

## 3. Функції моделі (`model.py`)

Орієнтовні сигнатури, уточнюються на етапі заглушок:

- `new_game(first_piece: Piece) -> GameState` — перша фігура вже віддана стороною FIRST: `current = first_piece`, `side = SECOND`, `action = PLACE`.
- `place(state: GameState, cell: Cell) -> GameState` — ставить `current` у клітинку; далі `action = GIVE` для тієї ж сторони.
- `give(state: GameState, piece: Piece) -> GameState` — `current = piece`, фігура зникає з `available`, сторона змінюється, `action = PLACE`.
- `outcome(state: GameState) -> Outcome`.
- `empty_cells(state: GameState) -> tuple[Cell, ...]` — за зростанням.
- `sorted_available(state: GameState) -> tuple[Piece, ...]` — за зростанням.

`IllegalMove`, якщо: не та дія, клітинка зайнята, фігура недоступна, гра вже закінчена.

Відсортовані функції потрібні для детермінованості: порядок перебору `frozenset` не гарантований.

## 4. Бот (`bot/`)

- Тип бота — функція: `Bot = Callable[[GameState], Move]` (аналог вказівника на функцію в Rust). Protocol не потрібен.
- Активний бот обирається константою в config.py.
- Одиниця глибини пошуку — півдія (один `place` або один `give`). Два рівні поспіль вибирає одна сторона: макс, макс, мін, мін.
- Порядок перебору фіксований: клітинки за зростанням, фігури за зростанням.

Боти
- `random_bot` — випадковий, сід від годинника. Навмисно недетермінований, лише для порівняння.
- `greedy_bot` — відповідає глибині 3 півдії: виграти постановкою, якщо можна; не віддавати фігуру, з якою суперник виграє одразу; серед рівних варіантів — найкращий за оцінкою, далі перший за порядком.
- `minimax_bot` — фіксована глибина `MINIMAX_DEPTH` у півдіях, оцінка в листках. Глибина підбирається вимірюванням так, щоб хід не перевищував 3.5 с. Чорновий варіант для демонстрації.

Оцінка (`evaluation.py`)
- `evaluate(state: GameState, side: Side) -> int` — спільна для жадібного бота і мінімаксу.
- Зміст — перший тиждень роботи, відкрите питання.

## 5. Презентер (`presenter.py`)

- Тримає: поточний стан, обрану фігуру (рамка першого кліку, `Piece | None`), активного бота.
- Обробляє: клік по клітинці, клік по фігурі, reset.
- Обирає випадкову першу фігуру, викликає `new_game`.
- Затримку ходу бота витримує через метод вікна `schedule`, сам tkinter не імпортує.
- Звертається до класу вікна напряму.

## 6. Вікно (`view.py`)

- Клас наслідує `tk.Frame`.
- Малює дошку, доступні фігури, поточну фігуру, рамку, статус, підсвітку лінії.
- Відсікає кліки не в ту фазу, решту передає презентеру.
- `schedule(ms, callback)` — обгортка над `after`.
- Модальне підтвердження Reset.
- DPI-awareness у v1.0 не вмикається (ADR 0019).

## 8. Заплановані зміни після v1.0

- Розділити `model.py` на `domain.py` (типи) і `rules.py` (правила).
- Увімкнути DPI-awareness для чіткого вікна.
- Protocol для вікна → тести презентера з фейковим вікном.
- Обмеження часом / iterative deepening замість фіксованої глибини.
