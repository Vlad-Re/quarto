# 0007. Functional core + MVP, чотири компоненти

Статус: прийнято.

Контекст: головний пріоритет — тестованість логіки без вікна; пізніше потрібні інші режими гри.

Рішення: ядро з моделі й бота (чисті функції, незмінний стан) і оболонка з презентера й вікна за схемою MVP. Порядок ходів живе в презентері, а не у вікні. Залежності: вікно ⇄ презентер → бот → модель; модель не залежить ні від кого.

Альтернативи: MVC (у tkinter View і Controller злипаються); MVP без функціонального ядра; три компоненти з об'єднаними моделлю й ботом.

Наслідки: ядро тестується без вікна. Незмінний стан спрощує пошук бота (немає відкату ходів), але зменшує кількість позицій, які він встигає перебрати.
