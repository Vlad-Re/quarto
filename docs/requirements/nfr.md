# Нефункціональні вимоги

## Performance Efficiency

- Час роздумів бота у v1.0 — не більше 3.5 с; це ж і критерій зупинки пошуку.
- Бажана перспектива — гра без прив'язки до часу, як у шахах.

## Interaction Capability

- Колірна гама у v1.0 не принципова, але всі 4 атрибути фігур мають бути візуально розрізнювані.
- Підказок при наведенні немає.

## Reliability

- Програма не крашиться від дій користувача.
- Закриття вікна в будь-який момент (зокрема під час розрахунку бота) коректно завершує програму, без процесів, що висять у фоні.

## Security

- Захист від чітерства не потрібен.
- Програма працює лише в межах папки проєкту.

## Maintainability

- Для розробки бажані тести (першочергово — визначення перемоги та критерії приймання ШІ).
- Форматування — Ruff; відступи під час набору — розширення Python Indent.
- Логіка гри та бот не залежать від GUI: бот отримує стан гри й повертає хід, GUI лише показує стан і передає кліки.

## Flexibility

- Файлів конфігурації (.env) у v1.0 немає.
- Архітектура має дозволяти пізніше додати режими «Гравець проти Гравця», «Бот ходить першим» і партії AI vs AI з підрахунком результатів. Турнірів у v1.0 немає; перехід до них (через Protocol) має бути безболісним.

## Safety

- Кліки по елементах, що не стосуються поточного ходу (наприклад, по фігурах на дошці), ігноруються.
- Потоків у v1.0 немає; під час розрахунку бота вікно не реагує (до 3.5 с).

## Compatibility

- Цільова система: Windows 11, ноутбук, масштабування 125%. Інші системи не критичні.
- Бажано не залежати від масштабування (рішення про DPI-awareness — на етапі дизайну).
- Розмір вікна фіксований.
