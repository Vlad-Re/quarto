# Вимоги до проєкту

## Ціль

Продемонструвати детермінований ШІ на прикладі гри Quarto.

## Скоуп

В: гра проти комп'ютера на одному пристрої, локальний UI.

Аут: мультиплеєр по мережі, гра людина-проти-людини, 3D-графіка, мобільна версія, скасування ходу (undo), збереження партії, екран налаштувань, звук.

## Критерії приймання (Acceptance Criteria)

Проєкт вважається успішним, якщо:

- програма запускається без крашів;
- користувач може провести повну партію від початку до кінця;
- алгоритм ШІ завжди блокує очевидний виграшний хід гравця (не робить дурних помилок).

Уточнення останнього критерію (щоб його можна було перевірити тестами):

- якщо бот може виграти постановкою поточної фігури, він виграє;
- якщо серед доступних фігур є хоча б одна, яка не дає гравцеві негайної перемоги, бот не віддає фігуру, що дає її;
- якщо безпечних фігур немає, програш неминучий і не вважається помилкою ШІ.

## Процес і версії

- Робота за SWEBOK. Версія 1.0 — швидка демонстрація, далі повернення до повного процесу.
- Керування конфігурацією: Git, приватний репозиторій на GitHub, одна гілка `main`.
- Документація зберігається в репозиторії у Markdown разом із кодом.
- Коміти англійською з префіксами: `docs`, `feat`, `fix`, `test`, `refactor`, `chore`.
- Реліз позначається тегом (`v1.0`).
