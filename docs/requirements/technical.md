# Технічні вимоги

## Мова та інструменти

- Мова — Python 3.14, версія фіксується у venv (`.venv` у корені проєкту).
- Інструменти: venv, Ruff (лінтер і форматер), Pylance / Pyright у режимі strict.
- Залежності розробки фіксуються в `requirements-dev.txt`, налаштування інструментів — у `pyproject.toml`.

## Алгоритми

- Алгоритми ШІ — детерміновані.
- Виняток: першу фігуру бот обирає випадково, для різноманітності партій. На силу гри це не впливає: інвертування будь-якого атрибута переводить набір фігур сам у себе й зберігає виграшні лінії, тому на порожній дошці всі фігури рівноцінні.
- Критерій зупинки пошуку у v1.0 — час (до 3.5 с). Наслідок: обраний хід може залежати від швидкодії машини.
- Ймовірнісні алгоритми (Монте-Карло, Лас-Вегас) — можливе розширення у v2 як бот для порівняння, не заміна детермінованого.

## Стандарти коду

- Типізовані сигнатури функцій і моделі даних (type hints).
- Незмінні моделі даних: `frozen=True`, `tuple` замість `list`, `frozenset` замість `set`, де можливо.
- Опційні значення — лише `T | None`, без `Optional[T]`.
- Вичерпність `match/case` перевіряє Pyright.
- Помилки — через винятки (exceptions), без бібліотеки returns.
- Protocol у v1.0 не використовується; з'явиться при додаванні інших типів гравців.
- Без мутування імен:

```python
# Погано
data = fetch_data()
data = clean_data(data)

# Добре
raw_data = fetch_data()
cleaned_data = clean_data(raw_data)
```

- Коментарі та docstrings — короткі англійські нотатки для себе, без жорсткої структури.

## Відкриті питання

- GUI-бібліотека (вирішується на етапі дизайну; перевірити підтримку Python 3.14).
- Фреймворк тестування (pytest чи unittest).
