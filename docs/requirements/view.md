# Вимоги до інтерфейсу

## Вікно

- Програма для одного користувача, для демонстрації викладачу.
- Одне головне вікно. Виняток у v1.0: модальний діалог підтвердження Reset (тимчасовий компроміс).
- Розмір вікна фіксований.
- Дошка 4×4, 2D, вид зверху.
- Окрема область з доступними фігурами; кожна фігура унікальна й після постановки переходить на дошку.
- Окрема область «поточна фігура».
- Кнопка Reset з підтвердженням.
- Рядок статусу: Player's turn (постав фігуру), Player's turn (обери фігуру для бота), Bot's turn, Player's win, Bot's win, Draw. Точні тексти фаз гравця — уточнити.
- Переможна лінія підсвічується.

## Хід гри

- Перший хід у гравця (пізніше буде можливість змінити).
- На початку партії бот випадково обирає фігуру й кладе її в «поточна фігура» до першого кліку гравця.
- Гравець клікає на порожню клітинку — поточна фігура ставиться одразу, без підтвердження.
- Потім гравець обирає фігуру для бота двома кліками: перший клік виділяє фігуру рамкою, другий клік по тій самій фігурі передає її боту.
- Клік по іншій доступній фігурі переносить рамку на неї; клік поза доступними фігурами знімає рамку.
- Асиметрія (постановка — один клік, передача — два) задумана.
- Ходи бота не бувають миттєвими: `BOT_MOVE_DELAY = 800` мс — мінімальний час ходу бота, навіть якщо розрахунок завершився раніше. Налаштовується в коді, без UI.
- Поки бот рахує, дії гравця заблоковані. Reset під час розрахунку у v1.0 не підтримується (буде у v2).
- Після будь-якого кінця гри (Player's win, Bot's win, Draw) дошка й вибір фігур блокуються до натискання Reset.

## Відмальовування фігур

Фігури малюються програмно, з чорним контуром:

- Форма (біт 1): 0 — коло, 1 — квадрат.
- Колір (біт 2): 0 — світла заливка, 1 — темна.
- Розмір (біт 3): 0 — 50% клітинки, 1 — 90% клітинки.
- Отвір (біт 4): 1 — поверх фігури маленьке коло кольору фону, 0 — суцільна.

## Відкриті питання

- Чи очищати кліки, накопичені під час розрахунку бота (залежить від GUI-бібліотеки).
