# Архітектура (v1.0)

## Стиль

Functional core, imperative shell + MVP (Model–View–Presenter).

- Функціональне ядро: модель і бот. Чисті функції над незмінними даними, без вікна, таймерів і випадковості.
- Оболонка: презентер і вікно. Тут живе все, що має побічні ефекти: tkinter, затримка, випадкова перша фігура.

Головний архітектурний пріоритет — тестованість ядра без вікна.

## Компоненти

Модель
- Незмінний стан гри: дошка, доступні фігури, поточна фігура, фаза / чия черга.
- Правила: поставити фігуру → новий стан; віддати фігуру → новий стан; перевірка перемоги й нічиї; дозволені ходи.
- Недозволений хід → виняток (сигнал бага в коді, а не реакція на користувача).
- Не залежить ні від кого.

Бот
- Отримує стан, повертає хід: клітинку для поточної фігури і фігуру для передачі.
- Пошук обмежений часом (до 3.5 с).
- Залежить лише від моделі.

Презентер
- Тримає поточний стан гри і стан вибору фігури (рамка першого кліку).
- Отримує від вікна події: клік по клітинці, клік по фігурі, reset.
- Викликає модель і бота, витримує `BOT_MOVE_DELAY`, обирає випадкову першу фігуру.
- Каже вікну, що показати.
- Звертається до класу вікна напряму (без Protocol у v1.0).

Вікно (tkinter)
- Малює дошку, доступні фігури, поточну фігуру, рамку, статус, підсвітку переможної лінії.
- Показує модальний діалог підтвердження Reset.
- Відсікає кліки, що не відповідають поточній фазі, решту передає презентеру.
- Не приймає рішень про гру.

## Правило залежностей

```
Вікно ⇄ Презентер → Бот → Модель
              └──────────────→ Модель
```

- Модель не знає ні про кого.
- Бот знає лише модель.
- Презентер знає модель, бота і вікно.
- Вікно знає лише презентер.
- Єдиний двосторонній зв'язок — вікно ⇄ презентер (властивість MVP).

Діаграми: `components.puml`, `turn-sequence.puml`.

## Перевірка ходів

Два рівні:
1. Вікно ігнорує кліки не в ту фазу (користувач нічого не помічає).
2. Модель кидає виняток на недозволений хід. Якщо це сталося — у вікні чи презентері баг.

## Час і потоки

- Один потік. Під час розрахунку бота (до 3.5 с) вікно не реагує.
- Затримка ходу бота — через таймер tkinter.
- Reset під час розрахунку у v1.0 не підтримується.

## Точки розширення (після v1.0)

- Protocol «учасник гри» → режими PvP, «бот ходить першим», AI vs AI.
- Protocol «вікно» → тестування презентера з фейковим вікном.
- Окремий потік для бота → Reset під час розрахунку.
- Швидше внутрішнє представлення в боті (мутації) без зміни інтерфейсу «стан → хід».

## Питання для етапу дизайну

- Представлення фігури, дошки і стану гри.
- Алгоритм пошуку і оцінка позиції.
- Як бот отримує ліміт часу (власний годинник чи дедлайн ззовні).
- Як презентер планує затримку, не залежачи від tkinter напряму.
- Чіткість вікна при масштабуванні 125% (DPI).
- Чи очищати кліки, накопичені під час розрахунку бота.
- Структура файлів у пакеті `quarto`.
